# OwnMem v2 设计定稿

> 状态：**已拍板**（2026-11-06 逐条讨论确认）；**P0 已实现**（v0.4.0）；**P1 已实现**（v0.5.0）
> 本文件是 v2 的唯一权威方案。动工、中转给其他 AI、日后修改，都以这里为准。
> 讨论过程中的证据与出处已内嵌，避免"为什么这么设计"需要考古。

---

## 0. 一句话定位

**跨 agent 记忆中间件**：所有 agent（WorkBuddy、Claude Code、TRAE、任何接 MCP 的）共用一套本地记忆账本。agent 随便换，记忆跟着人走。

不做 agent 运行时，不做调度，不做模型——那是跟字节 TRAE宝、DeepSeek 拼财力，拼不过也没必要。行业空档在别处：

- DeepSeek 产品经理亲口承认：跨会话长期记忆至今没有公认方案。
- TRAE 官方论坛用户喊"需要一个中间件"，官方回复是没有，只能手动维护 milestones.md。
- 2026 年全部主流记忆层（Mem0/Letta/Zep/Atlas/Cortex）都在卷"记得更准"，**没有一家做"你决定 agent 看见什么"**——这是 OwnMem 的墙。

---

## 1. 设计原则

1. **零第三方运行时依赖**（延续 v1，纯标准库，MCP stdio 自带实现）
2. **数据 100% 本地**，不出机
3. **控制权优先**：用户决定 agent 记住什么、看见什么，且全程有账（审计日志 + 会话回执）
4. **异步沉淀**：记忆写入发生在会话边界，不占对话响应（行业共识，见 §3.1 出处）
5. **借力不造轮子**：已被验证的机制直接搬，注明出处；没人做的才自己设计

---

## 2. 核心概念：三层账本

每条记忆 = 内容 + 元数据 `{agent来源, 项目/workspace, 类型, 时间}`。

| 账本 | 对应认知科学分类 | 记什么 | 例子 |
|---|---|---|---|
| **结论账** | semantic | 定稿的事实与决策 | "存储层定了 SQLite，不引 Postgres" |
| **过程账** | episodic | 当时的思路、为什么这么定 | "单机工具没有并发压力，运维成本更值钱" |
| **踩坑账** | procedural（教训版） | 哪条路走不通、为什么 | "WAL 模式放在网络共享盘上会一直锁死" |

**踩坑账默认全可见**——连盲审模式都不藏。理由（已拍板）：坑不是"影响"，是"遗产"，新 AI 不该把老 AI 踩过的坑再踩一遍。

依据：三账本分类是 2026 年行业标准（Elastic Atlas、Cortex、Mengram、各生产实践文章全用认知科学三分法），OwnMem 的划分正好对上，无需发明新词。

## 3. 功能清单（9 件，每件注明出处）

### P0 底座：把账记准

**3.1 会话结束自动沉淀**
- 会话结束 hook 自动提炼"这次干到哪了"的完整结论，落进对应项目层。堵住 v1 "记忆靠 agent 自觉写、结果长期零沉淀"的坑。
- 出处：行业共识。Letta 叫 sleep-time compute，Elastic Atlas 叫 background consolidation；Atlas 文档明确反对 inline 写入（拖慢响应）。

**3.2 项目隔离召回**
- 按 workspace 维度过滤，项目 A 的记忆不混进项目 B 的对话，召回命中率直接上升。

**3.3 三账本类型字段 + 元数据**
- 上面 §2 的账本分类落到存储 schema，是一切后续功能的地基。

**3.4 召回评分公式**
- `得分 = BM25 相关度 × 时间衰减 × 重要度权重`
- 出处：Cortex 五信号检索（相似度/时间/重要度/人物/渠道）的零依赖简化版。个人规模（<10 万条）BM25 足够，Cortex 用 Rust+SQLite 进程内跑也证明了不用向量库可行。

### P1 治理：让账本不烂

**3.5 取代链**
- 结论被推翻时不删旧条，标记"已被 XX 取代"并指向新条目，历史可追溯。
- 出处：Elastic Atlas 的 supersession links（新事实使旧矛盾事实失效但不删除，保留证据链）。

**3.6 踩坑计数器**
- 同一个坑被**不同 agent 或不同会话**再次踩中 → 该条踩坑账权重/可见性自动上调。"两家 AI 都栽过的坑"显然比"一家栽过的"更值得常驻。
- 出处：Atlas playbook 的 success/failure counters，改成多 agent 版（OwnMem 原创变体）。

**3.7 衰减 + 晋级**
- 记忆按重要度随时间衰减；同一件事被反复提到自动从"过程账"晋级为"结论账"。
- 出处：Cortex（高显著度记忆存活 3 倍时长；重复情节记忆晋级为语义事实）。治 Mem0 的著名弱点——无衰减、无限膨胀。

**3.8 注入预算管理**
- 每轮注入条数/字数有上限；always 级永远在场，其余按 §3.4 得分抢名额。
- 出处：DSH《Super-agent 设计探索》的 Inline/Spill（"浪费上下文窗口就是浪费模型的智能"），公开设计文档可白嫖。

### P2 视角：OwnMem 独有的墙

**3.9 四档会话视角**（把 v1 的"读记忆"一维拆细）

| 视角 | agent 能看到 | 用途 |
|---|---|---|
| `normal` | 全量 | 接着上一家干 |
| `result-only` | 只见结论不见思路 | 接手但保留判断 |
| `blind-review` | 隐藏旧 agent 的结论+思路+遗留物提示；踩坑账照常可见 | 挑毛病、发散（软盲审，见 §6） |
| `cross-check` | 全量 + 对抗提示："上一个 AI 的结论可能是错的，逐条验证再采信" | 交叉验证 |

- 对抗提示以**普通提示词**实现，不做成角色卡系统（角色卡已被砍，见 §6 注脚）。

**3.10 先答后对（一等公民功能）**
- 一条命令切两阶段：先盲审独立作答并存档 → 手动放开对照，让新 AI 挑自己的和上一版的差异。真人评审"先独立打分再对分"的做法，压训练趋同最有效的一招。

**3.11 分歧报告**
- 多个 agent 对同一任务都留有记忆时，自动生成"分歧对照表"：谁在哪一步用了不同假设、谁没提谁提了的风险。人只对分歧点做判断，不对整篇方案做判断——解决"AI 比我强所以我只会顺从"的问题（人只能判断分歧，判断不了趋同）。
- 出处：无直接竞品（全行业没人做），灵感来自人工评审流程。**这是 v2 的招牌功能。**

## 4. 多 agent 协同形态

- 每个 agent 接入时带身份（`OWNMEM_AGENT` 环境变量，v1 已有，扩展为每条记忆的来源标签）。
- 几个 agent 共用一套账本：结论共享、过程可隐藏、坑必共享、谁写的谁召回的全程有账。
- 交叉使用是**重活**，OwnMem 不把每轮都变评审会——用户按三条判据决定何时开交叉：①错了返工很久 ②两个 AI 曾给过矛盾答案 ③在乎但没法自己验证。其余时候顺从就是最优解。

## 5. 竞品地图（2026-11 快照）与不造的轮子

| 项目 | 路线 | 对 OwnMem 的关系 |
|---|---|---|
| Mem0（~49k★） | 扁平提取式记忆层 | 弱点=无衰减无限膨胀；定位重叠但方向不同 |
| Letta/MemGPT（~23k★） | 有状态 agent 平台，分层记忆 | 证明"跨 agent 共享记忆"有市场，但要求用它的运行时 |
| 腾讯 TencentDB Agent Memory（26k★） | 记忆资产+治理（可见性分级/Owner/审计） | **定位最像的对手**；但三服务重架构 vs 咱们零依赖单机 |
| Elastic Atlas（2026.7 开源） | 三库+后台沉淀+混合检索 | 机制的主要搬运对象（取代链/计数器/异步沉淀） |
| Cortex（Rust+SQLite 进程内） | 四层认知架构+衰减+置信度 | 哲学最接近（本地/单机/零网络），评分公式搬运对象 |
| Zep/Graphiti | 时序知识图谱（要 Neo4j） | 不学，太重 |
| DSH Superagent 原型 | Router+Worker 编排 | 不是产品且 Windows 不可用；设计文档当教材（Inline/Spill） |

**明确不造的轮子**：向量检索/embedding（个人规模 BM25 够用，省模型依赖）、知识图谱（要 Neo4j）、agent 运行时、角色卡系统（见下）。

## 6. 已知限制（诚实清单）

1. **文件遗留管不住**：上一个 agent 在项目目录留下的文件/代码改动，OwnMem 拦不住（它管注入不管磁盘）。缓解 = 遗留物登记 + 盲审模式下注入警告（"这些文件是上一个 AI 留的，读了会被它带偏"）。已拍板走**软盲审**（知情优先，不假装能强制）。
2. **权重趋同管不了**：模型层面的问题，上下文层只能压锚定。对冲手段 = 交叉用不同厂商的模型。
3. **角色卡已砍**（2026-11-06 拍板）。证据：①密歇根 EMNLP 2024（162 角色×2410 事实题×4 家模型：加角色不提升准确率，效果随机）；②沃顿 Prompting Science 4（2025.12，6 模型×每题 25 次：专家角色无稳定增益，错配角色致拒答，Gemini 42% 拒答）；③USC 2026（角色越长知识题掉分越多，71.6%→66.3%）。原理：角色是服装不是知识，占用注意力挤占知识检索。**残值**：行为类任务有效（安全角色越狱抵抗 +17.7%），故对抗提示保留为普通提示词。
4. **翻案注脚**：USC 同篇发现推理特化模型（reasoning-distilled）上专家角色反而加分。若未来接入推理模型的 agent，此结论需复评——记在这里防止将来考古。

### P1 实现记录（2026-11-06）

- **3.5 取代链**：`memories.superseded_by` / `supersedes`；`ownmem supersede <id> "新内容"`（= `add --supersedes`）；被取代的条 `status` 仍是 active（可查可追），但 `rank()` 默认过滤，`search --superseded` 考古。**取舍两条**：① 取代必须 `skip_dedup`——新旧结论常只差几个字，判重一挡等于功能失效；② 旧条若已被取代过则**在写入前就拒**，否则会白写一条平行记忆，那正是取代链要消灭的东西。
- **3.6 踩坑计数器**：`recurred` / `recurred_agents` / `last_recurred_at`；撞上已有踩坑账时**不新增条目**，只累加次数并把 agent 记进「栽过」名单（原始作者也算）。权重 `1 + 0.12×min(n,6) + 0.10×(不同agent数-1)`。复发在闸门层返回 `ok=True`（信息已被吸收），避免 agent 以为没记住而反复重试。
- **3.7 衰减 + 晋级**：`IMPORTANCE_DECAY`（low ×0.6 / normal ×1.0 / high ×1.15）叠在原有半衰期上，地板 0.35 不变；`promote_repeated()` 判据 = 召回 ≥5 次 **且** 出现在 ≥3 个不同会话，`session-end` 自动结算；`decay_report()` 只报告快淡出的，不动数据（遗忘该由人决定）。
- **3.8 注入预算**：预算值改为 `settings > 环境变量 > 默认`（`ownmem budget`）；裁剪从 **break 改 continue**——长条占满预算不该把后面三条短条全堵死；首条即超预算时仍硬收（原行为兜底）；`recall` 返回值新增 `budget` 报告。
- **迁移**：`SCHEMA_VERSION` 2→3，幂等补列；实测真实库 100 条活跃记忆升级后 **排序与命中完全一致**（分数尾差 1e-4，浮点乘序变化，无业务影响）；升级前备份 `~/.ownmem/ownmem.db.bak-v2-20261106`。
- **测试**：`tests/test_v2_p1.py` 44 项；全部旧测试回归通过（29+43+27+28+14）。
- **版本判定**：治理语义 + 新字段，P1 落地视为 v0.5.0。

### P2 实现记录（2026-11-06）

- **3.9 四档视角**：`sessions.view`（normal / result-only / blind-review / cross-check），与 mode **正交**——mode 管「能不能读」，view 管「读的时候看到什么」；blank/ghost 仍整体断读。过滤规则：result-only 隐藏过程账；blind-review 隐藏结论+过程+上次进度沉淀，**来源不豁免**（自己 agent 的旧结论同样锚定自己）；cross-check 全量 + 对抗提示词（行为指令，非角色扮演——角色卡已砍，见 §6.3）。踩坑账与常驻规则**任何视角都可见**（坑是遗产不是影响，已拍板）。盲审/交叉即使零命中也送出提示词（agent 得知道自己在什么视角下）。
- **3.10 先答后对**：状态存 settings KV（`af:{sid}` / `af_answer:{sid}`），不加 schema——会话级临时状态不值得动表。流程 `begin → submit → reveal → cancel`；independent 阶段屏蔽相关记忆与沉淀但**保留常驻红线**（红线是用户的规则，不是别人的答案）；compare 阶段注入独立方案**一字未改的原文** + 旧记忆 + 对照指令（「逐点对照、单独列分歧」）。submit 走 kind=process + tags=answer-first。MCP 侧 `answer_first` 工具，INSTRUCTIONS 明确要求 agent 第 1 阶段不许偷看（偷看等于作废整套机制）。
- **3.11 分歧报告**：新模块 `core/divergence.py`；BM25 收敛候选 → bigram+Dice 配对，**同话题由 BM25 保证，相似度窗口 [0.10, 0.90) 只滤复述与弱重叠**。下限 0.10 是实测修正——中文措辞不同的真分歧 bigram 相似度只有 0.1–0.2（「每周三更」vs「每周两更，质量优先」= 0.19），窗口定高了漏掉的恰恰是最值得上桌的分歧；代价是同话题不同侧面的条目也可能进窗，故措辞为「疑似分歧」并排展示，判断权留给人。只配**不同 agent**（同 agent 矛盾由取代链/判重处理）；已被取代的结论自动不上桌。CLI `ownmem divergence`，MCP `divergence_report`。
- **迁移**：`SCHEMA_VERSION` 3→4，`ALTER TABLE sessions ADD COLUMN view`（SQLite 中 view 作列名合法，已验证）；实测真实库 101 条活跃记忆升级后排序不变（唯一"差异"是时近衰减的时间漂移，非迁移副作用）；升级前备份 `~/.ownmem/ownmem.db.bak-v3-20261106`。
- **测试**：`tests/test_v2_p2.py` 39 项（含 v3 旧库升级、视角×模式正交、盲审不豁免来源、先答后对全流程、分歧配对的窗口两端）；全部旧测试回归通过（44+29+43+27+28+14）。
- **版本判定**：视角语义 + 新工具，P2 落地视为 v0.6.0。v2 至此全部落地。
